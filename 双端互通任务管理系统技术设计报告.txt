# 双端互通任务管理系统技术设计报告

## 1\. 项目概述

### 1\.1 项目简介

本项目是一套 **PC端 \+ 移动端双端互通的个人任务管理系统**，支持跨设备任务实时同步、离线编辑、任务待办管理、状态记录、时间提醒等核心能力。系统采用自研前后端分离架构，保障数据完全自主可控、同步稳定、隐私安全，适用于个人日常任务、工作待办、事项进度管理。

### 1\.2 项目目标

1. 实现 **Windows PC端（WPF）\+ Android移动端（Kotlin）** 双端数据双向互通。

2. 支持**离线优先**工作模式，无网络可正常编辑，联网自动同步。

3. 稳定的跨设备数据同步、冲突处理、软删除数据恢复机制。

4. 完整的用户登录鉴权、任务CRUD、任务分级管理功能。

5. 架构可扩展，后续可新增重复任务、消息提醒、标签分类、数据导出等功能。

### 1\.3 运行环境

- 后端服务：Windows / Linux 服务器，Node\.js 运行环境

- PC客户端：Windows 10 / Windows 11（\.NET 8）

- 移动客户端：Android 8\.0 及以上

- 数据库：MySQL 8\.0

## 2\. 整体技术架构

### 2\.1 架构模式

采用 **前后端分离 \+ 本地缓存 \+ 云端增量同步** 经典离线优先架构：

1. **客户端本地数据库优先写入**，保障离线可用、操作流畅

2. **云端服务统一存储全量数据**，作为唯一数据基准

3. **增量时间戳同步机制**，实现双端数据一致性

4. JWT全局鉴权，保障多设备登录安全

### 2\.2 整体架构链路

```Plain Text
WPF PC客户端（SQLite本地缓存） 
        ↕️ HTTP增量同步
Node.js Express 后端（MySQL云端数据库）
        ↕️ HTTP增量同步
Kotlin Android客户端（Room本地缓存）
```

### 2\.3 核心设计理念

1. **离线优先**：所有操作先写入本地数据库，不依赖网络

2. **增量同步**：仅同步变更数据，而非全量刷新，节省流量与性能

3. **时间戳冲突策略**：多端同时修改时，**最新修改时间覆盖旧数据**（个人场景最优解）

4. **软删除机制**：数据不物理删除，支持回收站恢复、避免同步丢失

## 3\. 全套技术栈明细

### 3\.1 后端技术栈（自研Node\.js）

- 核心框架：Express\.js

- ORM框架：Prisma（数据库迁移、类型约束、结构化建模）

- 数据库：MySQL 8\.0

- 鉴权方案：JWT 令牌登录、7天有效期

- 密码加密：bcrypt 哈希加密（无明文存储）

- 网络处理：CORS跨域、参数校验、异常捕获

- 同步核心：时间戳增量查询、批量数据 upsert 更新

### 3\.2 PC端技术栈（Windows）

- 开发框架：WPF（\.NET 8）

- 本地数据库：SQLite

- 数据ORM：EntityFramework Core

- 架构模式：MVVM（CommunityToolkit\.Mvvm）

- 网络请求：原生 HttpClient

- 序列化：System\.Text\.Json

- 核心能力：本地离线CRUD、待同步标记、增量上传/拉取

### 3\.3 Android移动端技术栈

- 开发语言：Kotlin

- UI框架：Jetpack Compose

- 本地数据库：Room

- 网络框架：Retrofit2 \+ OkHttp

- 异步处理：Coroutines \+ Flow

- 数据存储：DataStore（Token、同步配置持久化）

## 4\. 数据库详细设计

### 4\.1 云端MySQL数据表（Prisma建模）

#### 用户表 User

存储系统登录用户信息，密码加密存储

|字段|类型|说明|
|---|---|---|
|id|UUID|主键唯一ID|
|username|String|唯一用户名|
|password|String|加密密码|
|createdAt|DateTime|创建时间|
|updatedAt|DateTime|更新时间|

#### 任务表 Task（核心业务表）

|字段|类型|说明|
|---|---|---|
|id|UUID|全局唯一任务ID|
|userId|String|归属用户ID|
|title|String|任务标题|
|content|String?|任务详情备注|
|status|Int|任务状态：0待办、1进行中、2已完成|
|priority|Int|优先级：0普通、1重要、2紧急|
|dueTime|DateTime?|截止时间|
|isDeleted|Boolean|软删除标记|
|createdAt|DateTime|创建UTC时间|
|updatedAt|DateTime|修改UTC时间（同步核心字段）|

#### 标签体系表

- Tag 标签主表

- TaskTag 任务标签关联中间表（多对多）

### 4\.2 本地数据库设计（PC/APP统一）

两端本地表结构 **与云端完全一致**，额外增加本地专属字段：

- `IsPendingSync`：本地待同步标记

用于识别离线修改数据，联网后批量上传云端

### 4\.3 关键索引设计

1. 云端：`userId + updatedAt` 联合索引，大幅提升增量同步查询速度

2. 本地：`IsPendingSync`、`UpdatedAt` 索引，优化本地查询性能

## 5\. 核心业务接口设计

### 统一接口前缀

`/api/v1`

### 5\.1 鉴权接口

1. 注册：`POST /auth/register`

2. 登录：`POST /auth/login`

返回JWT Token，客户端全局携带鉴权

### 5\.2 任务同步核心接口

1. **增量拉取任务**  

`GET /tasks?lastSyncTime=UTC时间`  

功能：拉取当前用户 **晚于上次同步时间** 的所有新增/修改/删除任务

2. **批量上传本地变更**  

`POST /tasks/sync`  

功能：接收客户端离线变更数据，批量 upsert 更新云端数据库  

冲突策略：客户端传入的 `updatedAt` 时间戳作为最终数据依据

## 6\. 双端同步核心机制（系统核心亮点）

### 6\.1 同步整体流程

1. **本地操作**

新增/编辑/删除任务 → 写入本地数据库 → 标记 `IsPendingSync = true` → 更新 `UpdatedAt(UTC)`

2. **联网自动/手动同步**

- 第一步：**上传本地所有待同步数据** 到云端

- 第二步：**拉取云端所有增量更新数据**

- 第三步：本地比对时间戳，**新时间戳覆盖旧数据**

- 第四步：更新全局最后同步时间，清空待同步标记

### 6\.2 离线工作机制

- 无网络时：完全不影响新增、修改、完成、删除任务

- 所有变更永久保存在本地数据库

- 联网后自动合并至云端与其他设备

### 6\.3 冲突解决策略

采用**客户端时间戳优先策略**（个人任务系统最优方案）

- 同一任务双端修改 → **修改时间更晚的版本生效**

- 无需复杂字段合并，逻辑简单、稳定、无同步BUG

### 6\.4 软删除设计

- 不物理删除任何任务数据

- 删除仅标记 `isDeleted=true`

- 支持后续实现**回收站恢复功能**

- 彻底解决多端同步删除丢失数据问题

### 6\.5 时间统一规范

**全系统所有时间统一使用 UTC 标准时间**

- 彻底规避PC/手机时区不同导致的同步错乱、时间偏移问题

1. **完全自研可控**：无第三方BaaS依赖，数据私有、部署自由

2. **离线优先架构**：告别传统联网才能用的传统管理软件

3. **稳定的增量同步**：不做全量覆盖，性能优异、流量节省

4. **跨设备数据绝对一致**：UTC时间戳\+统一冲突策略

5. **软删除机制**：数据安全不丢失

6. **前后端标准化**：Prisma规范建模、JWT标准鉴权、RESTful接口

7. **双端技术栈成熟**：WPF稳定高效、Kotlin Compose现代化UI
